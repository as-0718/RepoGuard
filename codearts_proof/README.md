# RepoGuard 码道（CodeArts）使用证据清单

本目录归档在华为云码道 CodeArts IDE 中以「需求规格 → 实现方案 → 编码任务 → 任务执行」门禁式流程开发 RepoGuard 的关键界面截图，用于证明各阶段均经过独立核验后再落盘。

## 证据来源

- 截图取自码道 IDE 各阶段确认界面，原始文件来自系统剪贴板临时目录，已按阶段与时间顺序重命名归档。
- 时间跨度：2026-11-05 至 2026-11-08。
- 共归档 **27 张**，按阶段分目录存放；文件前两位序号表示同一确认点内的连续滚动位置。
- 另一类工程化证据（基线测试输出、冻结文件哈希、app.py 原始备份、静态校验脚本）保存在
  `.codeartsdoer/evidence/` 目录，与本目录截图互为补充。

## 目录与内容

### stage1_rules_engine（12 张）— 规则引擎
- `01_spec确认.png`：需求规格 spec.md 确认点（DFX 约束、数据结构、分级口径）。
- `02–04_design确认`：实现方案 design.md 确认点（路径约束、函数签名、依赖方向）。
- `05–06_tasks确认`：编码任务 tasks.md 确认点（任务规模、关键路径、各模块测试要求）。
- `07–12_编码验收`：编码执行完成验收（T01–T25 实际写入文件、135 测试全过、text/json 实跑、
  large_sample.mp4 如实标记「文件不存在」、验收核对）。

### stage2_web_api（8 张）— Web API + 单页控制台
- `01–04_spec确认`：需求规格确认点（设计定位、接口契约、错误码、白名单、单页方案、测试冲突）。
- `05–07_design确认`：实现方案确认点（请求流程、逐文件签名、路径安全、测试调整、4 项设计决策）。
- `08_编码验收`：编码执行完成验收（交付能力确认、环境说明，12 个文件已更改）。

### stage4_webhook_openapi（2 张）— Webhook + OpenAPI
- `01_design确认.png`：实现方案确认点（待确认的 7 项关键决策）。
- `02_tasks确认.png`：编码任务确认点（已落实的 7 项决策、进入编码执行确认）。

### stage5_dashboard_deploy（5 张）— 看板 + 部署 + 定时流水线
- `01–02_M1等待C2`：后端只读看板接口完成，端到端冒烟（四接口 200）、清理停止点。
- `03_M2等待C3`：Vue3 + ECharts 前端看板完成（两处取舍、25 文件已更改）。
- `04_M3偏差说明`：部署产物与定时流水线静态校验结果、偏差与 SKIP 声明。
- `05_最终交付.png`：阶段 5 最终交付结论（M1–M4 全部按确认点推进完毕）。

## 证据缺口（如实记录）

- **阶段 3（全仓健康巡检 + README 目录）**：当时未留存确认界面截图；其工程化结果由
  `.codeartsdoer/evidence/` 与全量测试回归（310 条）佐证。
- **阶段 4 编码执行验收**：仅留存 design/tasks 确认点，编码完成的界面未单独截图；由全量
  377 条测试与离线 Webhook 实测佐证。
- 部署/定时相关产物因本机无 Docker、nginx、hcloud、crontab，仅做静态校验，未执行项以
  SKIP 分列（见 stage5 截图与 `deploy/README.md`）。
