# AI 交互对话过程记录

## 说明

本记录梳理在华为云码道 CodeArts IDE 中「人—AI」的协作链条：每个阶段按 **需求规格 → 实现方案 → 编码任务 → 编码执行 → 验收复核** 的门禁推进，AI 先产出方案或代码，人工确认关键决策后再进入下一阶段。阶段确认界面截图见同目录各 `stage*/` 子目录；工程化佐证见 `.codeartsdoer/evidence/`。

## 阶段 1：规则引擎

- **人提出的目标**：面向课程与社团共享仓库做提交前自检，覆盖命名/目录、代码注释与写法、Markdown 链接、敏感信息与大文件；问题需要分级。
- **AI 产出**：规格（DFX 约束、数据结构、分级口径）→ 方案（路径约束、函数签名、依赖方向）→ 任务清单（任务规模、关键路径、各模块测试要求）→ 编码与验收。
- **人工确认与决策**：确认问题分「必须修改 / 优化建议」两级；路径不能跳出仓库；中文文件名只给优化建议、不阻断提交；验收时 135 项测试全过，text/json 两种格式实跑，缺失文件如实标记「文件不存在」。
- **对应截图**：`stage1_rules_engine/01–12`。

## 阶段 2：Web API + 单页控制台

- **人提出的目标**：把规则能力封装成只读 HTTP 接口与单页控制台，要求路径安全、仓库白名单。
- **AI 产出**：规格（接口契约、错误码、白名单、单页方案、测试冲突）→ 方案（请求流程、逐文件签名、路径安全、4 项设计决策）→ 编码验收。
- **人工确认与决策**：确认白名单只读取环境配置内目录、请求参数不能覆盖；单页以静态文件托管；本阶段共 12 个文件更改。
- **对应截图**：`stage2_web_api/01–08`。

## 阶段 3：全仓巡检 + README 目录

- **人提出的目标**：对整个仓库递归巡检，统计问题与僵尸候选；生成 README 目录索引并与现有 README 做差异对比。
- **AI 产出**：巡检服务、僵尸候选识别、README 扫描/索引/对比模块及对应测试。
- **人工确认与决策**：确认工具不直接改写 README；降级项与无法判定项如实单列。
- **截图情况**：本阶段未留存确认界面截图，相关结论由代码与全量回归测试佐证（见 `build_refactor_debug_log.md`）。

## 阶段 4：Webhook + OpenAPI 回写

- **人提出的目标**：支持离线可测的事件回写，包含签名校验与幂等处理。
- **AI 产出**：方案（待确认的 7 项关键决策）→ 任务清单（决策落实、进入编码）→ 编码与离线端到端实测。
- **人工确认与决策**：确认幂等键设计、签名校验方式与离线测试口径。
- **对应截图**：`stage4_webhook_openapi/01–02`（仅留存方案与任务确认点；编码完成界面未单独截图）。

## 阶段 5：看板 + 部署 + 定时巡检

- **人提出的目标**：用 Vue 3 + ECharts 做只读看板；产出部署与定时巡检模板。
- **AI 产出**：M1 后端只读看板接口（四接口 200 冒烟）→ M2 前端看板（两处取舍、25 个文件更改）→ M3 部署/定时产物静态校验与偏差声明 → M4 最终交付。
- **人工确认与决策**：确认缓存 TTL 60 秒 / LRU 8、仅单实例；部署产物仅做静态校验，未执行项以 SKIP 分列。
- **对应截图**：`stage5_dashboard_deploy/01–05`。

## 贯穿全程的交互原则

1. 每个门禁经人工确认后再进入下一阶段，不跳过规格与设计直接写代码；
2. 未通过、未执行的项如实标注，不记作通过；
3. 以冻结文件哈希与基线测试回归作为复核依据，防止改动越界。
