# 码道（CodeArts）在项目开发中的应用总结

## 一、协作模式

项目在华为云码道 CodeArts IDE 中按**门禁式五阶段**推进：

> 需求规格（spec）→ 实现方案（design）→ 编码任务（tasks）→ 任务执行（编码）→ 验收复核

每个门禁先由 AI 产出方案或代码，经人工确认关键决策后才进入下一阶段；不跳过规格与设计直接写代码。各阶段确认界面截图归档于 `codearts_proof/`。

## 二、五阶段与产出

| 阶段 | 模块 | 主要产出 | 证据目录 |
|---|---|---|---|
| 阶段 1 | 规则引擎 | 命名/目录、代码、链接、敏感信息与大文件四类检查；问题分「必须修改 / 优化建议」两级 | `codearts_proof/stage1_rules_engine/` |
| 阶段 2 | Web API + 单页控制台 | 只读检查接口、健康检查、仓库白名单、单页静态控制台 | `codearts_proof/stage2_web_api/` |
| 阶段 3 | 全仓巡检 + README 目录 | 递归巡检、问题与僵尸候选统计、README 目录生成与差异对比 | 无界面截图，由代码与全量回归测试佐证 |
| 阶段 4 | Webhook + OpenAPI 回写 | 签名校验、幂等处理、离线端到端实测 | `codearts_proof/stage4_webhook_openapi/` |
| 阶段 5 | 看板 + 部署 + 定时巡检 | Vue 3 + ECharts 看板、部署产物、定时巡检模板 | `codearts_proof/stage5_dashboard_deploy/` |

## 三、AI 在各环节的具体作用

- **需求拆解**：把「课程/社团共享仓库需要自检」的模糊目标，转成规格约束、数据结构、分级口径与验收条件。
- **方案设计**：确定函数签名、模块依赖方向、路径安全边界、接口契约与错误码。
- **任务编排**：把方案拆成可独立验收、可单独测试的编码任务。
- **实现与测试**：生成功能模块与对应单元测试，按模块逐步落地。
- **复核纠偏**：冻结文件哈希核对、基线测试回归比对、既有失败项如实标注，不把未通过的项算作通过。

- 阶段 3、阶段 4 的编码完成界面未单独留存截图，相关结论由全量回归测试与离线实测佐证。
- 部署与定时巡检产物因开发本机无 Docker、nginx、cron 等环境，仅做静态校验，未实际上线、未上云。
- 仓库内出现的弱口令、示例令牌均为规则检测用测试样本，不是真实凭证。
